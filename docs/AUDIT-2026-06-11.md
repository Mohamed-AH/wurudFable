# Repository Audit & Improvement Plan — wurudFable

**Date:** 2026-06-11
**Method:** Multi-agent audit per `claude.md` architecture rules — Fable 5 orchestrator; Haiku subagents for read-only navigation/mapping; Sonnet subagent for independent install/audit/test verification. All findings below were either verified first-hand by the orchestrator (marked ✓) or reported by a subagent and spot-checked where high-impact.

## 1. Executive Summary

**Overall health grade: B-.** This is a real, live production service (rasmihassan.com) with genuinely strong fundamentals — comprehensive input validation, auth on every mutating route, 56 test files with CI running against real MongoDB, Sentry + Prometheus observability, and thoughtful caching for a 512MB host. What pulls the grade down is maintainability and hygiene, not correctness: a 2,700-line admin route god-file, 7 failing unit tests that likely break CI right now, 16 production dependency vulnerabilities (6 high), no linting at all, and a repo root drowning in ~20 contradictory session-artifact markdown files with no README.

**Top 3 risks:** (1) `passport.test.js` failures mean the CI critical gate is likely red, normalizing broken builds; (2) high-severity dependency advisories — including a Mongoose `$nor` NoSQL-injection issue — are unfixed and CI's audit step is `continue-on-error`, so nothing forces action; (3) an open redirect via `returnUrl` plus a public `/debug-sentry` crash route and `sendDefaultPii: true` form a cluster of small, cheap-to-fix production security/privacy holes.

**Top 3 opportunities:** (1) ~2 hours of quick wins eliminates every High security finding; (2) extracting the duplicated lecture-aggregation pipeline and splitting the admin god-file would make all future feature work materially cheaper; (3) adding ESLint + raising the 5% coverage threshold converts the existing strong test suite into an actual regression gate.

## 2. Repo Map

**Purpose:** Arabic-first platform for streaming/downloading ~160 Islamic audio lectures (~3.4GB on Oracle Cloud Object Storage), with a Google-OAuth-protected admin panel. Production service, actively maintained, migrating Render → OCI.

**Stack:** Node.js 20 / Express 4 / MongoDB Atlas (Mongoose 8) / EJS + express-ejs-layouts / Passport Google OAuth / Sentry + prom-client / Jest + Playwright / Docker + PM2 + Render + nginx configs.

**Architecture sketch:** Single Express entry (`server.js`, 318 lines) → 20-step middleware stack (Helmet, rate limits, session w/ Mongo store, Passport, i18n, analytics, DB-health fail-fast) → routes mounted at `/`, `/auth`, `/admin`, `/api/*`, `/stream`, `/download`, `/search`. **Business logic lives inline in route files** — `controllers/` contains only `streamController.js` (409 lines, used by `routes/stream.js`). Models are well-indexed Mongoose schemas; a singleton `SiteSettings` and atomic `Counter` drive config and shortIds.

## 4. Improvement Strategy

**Theme 1 — The safety net exists but isn't load-bearing.** Tests are plentiful but the gate is broken (C1) and the thresholds are decorative (C3); audit and lint never fail CI (S4, A3). *Target state:* CI red means something — failing tests, lint errors, and new high-severity advisories all block merge. *Principle:* automate the standard you already have, don't raise the standard.

**Theme 2 — Cheap production security/privacy holes.** S1–S5 are each ≤30-minute fixes with outsized exposure. *Target state:* zero High security findings; `npm audit --omit=dev` clean of fixable highs. *Principle:* fix everything where effort ≈ minutes and exposure is public.

**Theme 3 — Route-file monoliths tax every future change.** A1/A2 explain most of the duplication, sync-I/O, and missing-`.lean()` findings — code written into giant files escapes scrutiny. *Target state:* admin panel split into ~6 resource routers with shared helpers; one shared lecture-pipeline builder. *Principle:* split along the resource boundaries the URL space already defines; no framework changes, no controller-layer dogma.

**Theme 4 — The repo doesn't explain itself.** No README, 94 undocumented scripts, contradictory guides. *Target state:* README as front door, session artifacts archived under `docs/archive/`, scripts catalogued with a DANGER column. *Principle:* archive, don't delete — they're useful history in the wrong place.

**Explicitly NOT recommended (trade-offs):** TypeScript migration (huge effort, solo-maintainer project, tests provide the safety net); replacing the in-memory cache with Redis (single-instance deployment, OCI move adds RAM headroom); restructuring i18n (A6 — fine at 2 locales); redesigning fire-and-forget metrics (P6 — correct trade-off as is); CSP nonce refactor beyond removing what's removable (S6 — schedule with a views-cleanup pass, not before); paying for SheetJS Pro (xlsx is admin-only input — switch to `exceljs` opportunistically instead).

**Definition of done (measurable):** CI green on `main`; lint job exists and fails on error; `npm audit --omit=dev --audit-level=high` exits 0 except documented xlsx exceptions; zero High findings from this report open; coverage threshold ≥60% on `routes/`, `utils/`, `middleware/`; `routes/admin/index.js` < 500 lines; README exists; root has ≤5 markdown files.

### Implementation sketches (top 3)

**1. QW1 — returnUrl open redirect (S).** Grep for every `res.redirect(req.body.` and `res.redirect(req.query.` occurrence (don't fix only line 275). Add `utils/safeRedirect.js`: accept only same-origin paths (`/^\/(?!\/)/` — leading slash, not protocol-relative `//`), else fallback. Gotcha: protocol-relative `//evil.com` passes naive "starts with /" checks — the regex must reject a second slash. Add unit test with `//evil.com`, `https://evil.com`, `/admin/lectures?x=1`.

**2. M0.1 — passport.test.js mocks (S).** Failure mode is `Admin.findOne(...).lean is not a function`: production code calls `.findOne().lean()` but mocks return a plain promise. Fix: `jest.fn().mockReturnValue({ lean: jest.fn().mockResolvedValue(adminDoc) })` — or a small `mockQuery(result)` helper since multiple tests need it. Gotcha: some assertions may also await the un-leaned path; align with the real call shape in `config/passport.js` rather than guessing. Verify with `npx jest tests/unit/config/passport.test.js`, then full suite.

**3. M2.1 — admin god-file split (XL → ~6×M).** Mechanical extraction, zero logic change: create `routes/admin/lectures.js` etc.; move handlers verbatim; hoist shared imports/middleware (`isAdmin`, `adminI18n`, multer config) into `routes/admin/shared.js`; `routes/admin/index.js` becomes ~40 lines of `router.use('/lectures', …)`. Gotchas: (a) Express route ordering — keep specific routes (`/lectures/bulk-upload`) mounted before parameterized ones (`/lectures/:id`); (b) module-level state in the current file (multer instances, cached values) must move to `shared.js`, not be duplicated; (c) do one resource per PR with the integration suite green between each.

## 6. Open Questions (need a human decision)

1. **Dual Sentry config:** `instrument.js` and `config/sentry.js` both call `Sentry.init` with overlapping settings. Which is authoritative? (Suspect `config/sentry.js` is dead since `server.js:2` only requires `instrument.js` — confirm before deleting.)
2. **xlsx dependency:** the two unfixable advisories are tolerable only if XLSX parsing stays admin-only. Is bulk-upload-via-Excel a permanent feature (→ migrate to `exceljs`), or legacy (→ remove the dependency)?
3. **`scripts/` triage:** which of the 94 scripts are still operationally needed (OCI sync, slug fixes) vs. one-time migrations? Only the owner knows which are safe to archive.
4. **Rate-limit numbers:** `generalLimiter` at 100 req/15min would throttle a legitimate binge-listener loading pages + streaming. What's the intended per-user budget for `/stream`?
5. **Performance targets post-OCI:** the 512MB-driven constraints (cache size, memory caps in `ecosystem.config.js`) — keep for discipline or relax on the 6GB host?
6. **CI red status:** are the 7 `passport.test.js` failures known/pre-existing on `main`, or a recent regression? (Determines whether M0.1 is a fix or a revert-hunt.)
